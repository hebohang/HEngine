# 调度与恢复协议

## 启动与持久记录

先发现并核对可用的 `list_projects`、`create_thread`、`read_thread`、`wait_threads`、`send_message_to_thread` 工具及当前 schema。选择与当前目录匹配的项目，不能凭名称猜项目 ID。用户默认约定使用当前目录，因此创建时显式选 `environment.type: local`，不使用从默认分支创建的新 worktree。

读取仓库指导、当前分支、HEAD、upstream、remote、staged/unstaged/untracked 摘要。保存初始改动清单；用户既有改动不自动纳入本项提交。若本项必然混入无法区分的既有改动，先集中澄清范围。

解析前通过 `git rev-parse --path-format=absolute --git-common-dir` 取得 Git 元数据目录，在其 `prompt-scheduler/<batch-id>/` 中保存小型调度记录；不同 worktree 共用该目录便于发现冲突队列。此处仅放原始消息、解析结果和状态，不放截图、构建物或性能数据。后者走项目正式 Storage 流程。

使用唯一 batch ID；原文文件只创建一次，不覆盖旧批次。`state.json` 记录：

- schemaVersion、batchId、projectId、绝对工作目录、branch、initialHead、upstream、初始改动清单。
- 用户执行、提交及推送授权来源摘要、显式模型/环境要求、总控任务 ID（能够取得时）。
- 每项 index、标题、完整 prompt 文件位置/哈希、status、threadId/clientThreadId/hostId、wait cursor。
- 后台检查间隔（如需，保留用户指定值）、automationId、lastCheckAt、nextCheckAt；真实事件订阅可用时另记订阅标识。
- startHead、验收清单、证据位置、权限检查结果、commit hashes、remote/branch、remoteHead、阻塞原因及时间。

状态可使用 `pending / creating / checking_environment / running / verifying / pushing / completed / blocked`。只有总控更新队列；执行任务回报结果。每次创建前后、收到最终输出、验收、提交推送核实、阻塞时保存。写临时 JSON 后原子替换 `state.json`，保留上一版备份。

启动或恢复必须先查找同工作目录/分支的未完成队列。使用原子独占创建的 owner/lock 文件防止两个总控同时操作，记录总控任务 ID 和批次。存在锁时核对该总控和执行任务状态；不按文件年龄自动抢锁，不擅自运行第二个队列。状态不能确定时报告歧义。只释放自己持有的锁；中断后保留恢复记录。

## 创建与实施

每项通过 `create_thread` 创建一次，标题包含批次、序号和简短目标。创建前记录 `creating` 及可检索的唯一标识；仅传入用户明确指定的 model/thinking，其余沿用工具默认。

首条消息传入完整原文、目标路径/分支、批次标识及下述执行信封。要求执行任务核对自身路径、分支、实际所需能力和用户显式环境要求，满足后直接实施，无需额外握手回合；具体能力不足时说明受阻操作及证据，保留未完成状态。

不以“完全访问”作为默认门槛，不编造工具参数、从父任务推断子任务权限或声称 prompt 授予了权限；不绕过审批或自行修改全局设置。

返回 clientThreadId 表示建立中时，将其单独保存，不能作为 threadId 调用后续工具。通过工具提供的状态或 `list_threads` 中唯一标识解析到真实 threadId。创建超时或返回不确定时先查找已有任务，不直接重试创建。不能唯一识别时停止派发并保留记录。

保存创建任务对应的应用指令；最终回复按应用要求输出 `::created-thread{threadId="..."}`，仍仅有 client ID 时使用 clientThreadId 形式。

## 执行信封

将以下内容与完整 prompt 清楚分隔，不修改正文：

- 这是用户明确授权的串行队列第 N/M 项。仅负责本项，不创建下一项，不改队列文件。
- 使用指定目录/分支及当前源码，遵守 AGENTS.md 与适用技能；保留列出的初始用户改动。
- 上项完成情况及简短交接信息；原始正文完整附后。
- 形成验收清单并完成全部阶段。阶段结束或发出最终回复不等于完成；未验证项不得标为 PASS，客观阻塞保留未完成。
- 自主完成本项实施、必要验证、修复及已授权 Git 操作，最后统一回报；中途进度不需要总控批准。仅缺少必要输入时提出明确问题。
- 明确附上用户的执行、提交和推送授权及限制。需要提交或推送时，在必要验收通过后读取 `C:/Users/51906/.codex/skills/git-commit-push/SKILL.md`，仅执行已授权操作。路径不存在时搜索同名已安装技能；找不到且本项需要它时报告阻塞。
- 遵循提交 skill 对远程分叉、hooks、歧义范围等约束，不强推、不自动合并或变基、不越过 hooks。真实验收失败时不按成功提交推进队列。
- 回报 completed/blocked、逐项验收结果、精确验证命令与证据类型、剩余项、commit hash、remote/branch、推送核实结果及未提交文件。没有实际改动则解释原因并报告 no-change，不制造空提交。
- 清理自己启动的运行会话，遵循项目 check/capture 与 finally stop 约定。

## 等待与验收

当前回合优先对执行任务使用有界 `wait_threads`（单次不超过 60 秒），复用 hostId 和返回 cursor。完成或需要输入时立即处理；超时可继续有界事件等待，不循环零超时查询、不反复读日志，也不使用 shell/sleep 模拟调度。沿用用户明确指定的等待方式和检查间隔。

仅需在当前回合结束后恢复调度时，发现并使用 `automation_update`，按当前 schema 创建附着于**原总控任务**的 heartbeat。先查找同队列已有自动化并优先复用，保存 automationId。采用用户指定间隔；未指定时按任务预计耗时选择、记录并告知检查间隔及可能延迟。用户显式选择的 4/8 小时等间隔继续适用。仅编辑 skill 不创建自动化、抢锁或继续队列。

heartbeat 的用户可见 prompt 应说明：读取本批次状态记录，仅对当前执行任务调用一次 `wait_threads(timeoutMs: 0)`，复用 cursor；若仍在运行，保存检查时间和 cursor 后安静结束本次唤醒，不分析返回的中途 commentary、不读取详细日志或源码、不发送提醒。只有收到最终结果或明确的必要输入/失败状态时，才读取相关结果并处理。保持不变或无需处理时不通知用户；仅在验收完成、真实阻塞或需要用户行动时通知。整队列完成或因阻塞暂停后暂停该 heartbeat，恢复队列时复用原自动化。

使用原总控的持久记录和锁归属恢复调度，确认当前项完成并验收后再创建下一项，不产生第二个总控或重复派发。后续仍需后台恢复时复用同一 heartbeat。

`wait_threads` 仅在调用期间等待事件；不能假定 `create_thread` 会在总控回合结束后自动唤醒它。真实后台完成订阅可用时可提前验收；heartbeat 可能延迟一个检查周期，离线时更久，不能称为即时回调。定时工具不可用不妨碍当前回合继续有界等待；需要离开时保存恢复记录并说明不能自动唤醒。

运行中的阶段进度和暂时失败不触发总控干预；仅用户要求停止/调整任务或执行任务请求必要输入时处理中途交互。详细证据留到最终回报后核对，向用户报告状态不等于向执行任务发送催促。

任务最终回复后，对照完整 prompt 的验收清单核对实际文件、报告、测试和运行证据。不能只根据它写了 completed 就放行，也不用重跑已经充分覆盖的昂贵验证。缺阶段、仅交付方案或还可继续修复时，向同一任务发送明确剩余清单继续推进。无进展的相同失败不无限重发“继续”，保存证据并说明阻塞。

推进前独立核对工作目录/分支及本项结果。提交已授权时核对预期提交及应提交的遗留改动；推送已授权时通过 fetch 或 ls-remote 核对远程 ref，不能仅凭旧 tracking ref 放行。只提交时不要求远程同步，不提交时允许保留本项预期改动并交接。no-change 需确认正文要求实际满足，且确无本项改动。

成功后记录 completed 及实际 Git 结果，再创建下一项。本项必要验收或已授权操作的真实阻塞不得降标、跳项或虚构完成；用户改变要求时记录授权再调整队列。

## 恢复

恢复时读取 state、原始 prompt 和锁归属，核实目录/分支、对应任务状态及已授权 Git 操作。已有活动任务继续等待；已结束但未验收的补验收；仅在推送已授权且未完成时补推送；已完成但未记录的补记录。不要重做已经完成的工程或重复提交。

若记录不完整，根据创建标识、任务历史和 Git 证据恢复。不能确认某项是否已经启动时，先解决不确定性再创建任务。恢复不依赖长对话完整历史，也不把旧摘要代替 prompt 原文。
