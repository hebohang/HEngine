# Transient texture reuse

`Rendering.Memory.TransientTextureReuse` is an independent, default-off RenderSettings switch. It creates a candidate resource pool through the existing all-view configuration transaction. Reference and candidate shaders, resolution, ray counts and filters are identical.

The allocator reuses the same NVRHI texture object, not different placed resources sharing a native heap. Candidates must have matching shape/format/clear values and sufficient resource capabilities. Every lifetime already assigned to that object must be strictly disjoint from the new lifetime. Intervals sharing a pass cannot reuse storage. Resource declaration order is not treated as execution order.

Only transient, non-exported, initially uninitialized textures in the same graph namespace and frame slot participate. Imported histories and assets, persistent resources and buffers keep their ownership. Existing frame-slot completion fences remain mandatory. This relies on the current graph executing one ordered command list; enabling genuinely concurrent graph queues would require a different lifetime model first.

Resource-state tracking begins once per physical transient texture, and final transitions are deduplicated by physical pointer. NVRHI still inserts required UAV and usage transitions. Separate pools are prepared for configuration changes; the previous pool is retired by its submission fence. This change does not remove candidate/old-pool overlap or account nominal pool bytes as total VRAM.

The `RenderGraphResourcePool` unit test covers disjoint/reverse-order intervals, overlaps, multiple assigned intervals, graph isolation, excluded resources and the existing slot-fence contract. GPU validation and native image comparison are separate evidence. Existing allocation records expose logical intervals and physical IDs. Actual pool and device memory measurements, rather than the theoretical reuse count, determine the benefit.

Validation note (2026-09-08): DX12 SurfaceCoverage, Deferred, native 3840x2160, 180 simulation frames, same Native4KComparable values except this switch. After resetting TAA/GI/postprocess history at runtime startup completion, on/off PNG comparison has 99.99673675% identical RGB channels, maximum difference 1/255, mean absolute error 0.00003263. This is static image equivalence evidence, not animated/multiview/Vulkan acceptance. Earlier on/off captures used unequal pre-game sampling epochs (198 vs194 total GPU samples) and must not be used for equivalence conclusions. Three-slot nominal transient reservation fell from 3,828,429,108 to 3,094,374,708 bytes in the preceding 60-frame short timing pair; measured GPU span was ~25.28 vs25.26 ms, no meaningful frame-time improvement on this small scene. The feature remains default off pending complex-scene and backend regressions.

`render.graph.snapshot` resources include `physicalTextureGroup`, a snapshot-local identity shared by logical textures that resolve to the same NVRHI texture. Zero means unrealized; this is neither a native address nor a global allocation ID. `Test-RenderingPaths.ps1 -TransientTextureReuse` explicitly enables reuse in its configuration transactions and retains resource pages for auditing.

Configuration storage correction (2026-09-08, runtime validation pending): the native Vulkan regression exposed allocation failure even with a single preallocated candidate bank; later frame-slot growth also failed after commit. That approach is replaced by preparing all banks again, seeded with references to completed active transient allocations. Candidate metadata is independent, persistent resources and imported history are not shared, and only one graph is ever executed after commit/abort. Preparation explicitly waits for the last active GPU work when required, then uses normal pool shape/capability matching. Thus matching allocations are not doubled during preparation, and each post-commit bank has already been proven. The wait is included in preparation/transaction latency. Nominal old plus candidate pool bytes double-count shared resources and must not be reported as VRAM. The prior `paths-one-bank-vulkan-native4k` run has 11 FAIL results and is retained as a failed experiment.
