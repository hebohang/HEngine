# Prompt 调度器

用户直接粘贴 prompt；调度器保存原文与进度，不要求用户另建文件。

## 输入

```text
$prompt-scheduler

【任务 1】
第一个完整 prompt。

【任务 2】
第二个完整 prompt。
```

- 首项 `【任务 1】` 可省略；无标记时，全部正文就是任务 1。
- 标记必须独占一行，形式为 `【任务 N】`，允许首尾空白，编号从 1 连续递增。按输入顺序执行，不按推测的依赖重排。
- fenced code block 内的标记、行内标记、正文阶段和编号不分割任务。需要在正文展示标记时放入代码块。
- 空任务、跳号、重复编号、未闭合代码块在创建任何任务之前报出；不猜测修复后启动。
- 使用 `scripts/parse_prompts.py` 解析原始消息。支持 `--input <UTF-8文件>` 或 stdin；输出包含完整原文的 JSON 必须通过 `--output` 写盘，不向对话打印长正文。输入临时文件也由调度器创建，不要求用户填写。
- 保留原文；不擅自删减、合并或用摘要替代正文。UI 若将长文转为附件，应读取用户指定附件再解析；不能只使用附件标题。输入缺失或截断时先解决，不启动残缺任务。
- 只有技能名或空白时展示上述填写模板，等待正文。用户要求查看、继续、暂停队列时，将其作为控制请求，不当成新的单项 prompt。

## 默认执行约定

- 项目为当前 HEngineDev，串行使用启动时确认的同一工作目录和分支，下一项继承上一项完成的代码。
- 每项新建独立 Codex 任务。仅传入用户明确指定的 model/thinking，否则省略并沿用工具默认；不静默替换用户指定但不可用的模型。
- 首条消息包含完整正文；执行任务核对路径、分支及本项所需能力后直接实施，不单独等待权限握手。仅必要能力不足或用户明确要求的环境不满足时保存阻塞。
- 将已有的整批执行、提交和推送授权准确传入执行任务。必要验收通过后，按实际授权使用 `git-commit-push`；只提交不推送、无需提交等用户选择同样适用，不重复询问已授权操作。
- 仅咨询、预览、解析格式、安装或调用技能名称本身不扩大执行及 Git 授权。
- 正文可以授权该项内部并行子代理，但总控始终仅启动一个执行任务；同 GPU 的运行与基准不得并发。
- 执行任务自主完成，总控在最终回报后验收；仅用户要求停止/调整或执行任务请求必要输入时中途介入。
- 当前回合用有界 `wait_threads` 等待完成并推进队列；仅跨回合恢复需要时使用总控 heartbeat。沿用用户指定的检查间隔，不把固定小时级检查作为所有任务的推进门槛；细节见调度协议。

## 工作流程

实际启动或恢复前读取 [调度与恢复协议](references/orchestration.md)。

1. 解析并保存队列、项目上下文及初始改动；展示数量和简短标题。格式合法且已有执行授权时直接开始。
2. 按协议逐项创建、等待及验收；可完成的缺项反馈给同一任务。当前项成功并保存记录后才创建下一项，真实阻塞不跳过。
3. 报告任务入口、验证及实际 Git 结果；有阻塞时说明当前项、原因和未执行项。

查看进度只读记录及对应任务；继续时先对照真实状态，不重复创建或推送。暂停时停止新任务派发；若用户要求停止当前工作，通知执行任务在安全点收尾并等待其确认，不能仅将本地状态改为已停止。

## 使用边界

本 skill 依赖桌面任务管理工具；不可用时说明缺失能力，不擅自改为在总控执行。`agents/openai.yaml` 提供填写模板，不保证键入技能名就插入模板。

落盘支持断点恢复，不保证应用退出、机器休眠或额度耗尽后仍执行。此工作流允许创建或更新一项用于完成检查的总控 heartbeat；仅编辑本 skill 时不创建实际自动化、不接管正在执行的队列。不要另建后台服务或修改全局权限配置。
